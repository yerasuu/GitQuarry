# v0.4.2

Range: `v0.4.1..v0.4.2`. Workspace `0.4.1` -> `0.4.2`. No deploy step.

## Fixed

- `domain::merge_request::diff_endpoints` returned `(target_branch, source_branch)` for a merged MR whose branch still existed. The source is an ancestor of the target by then, so `git diff base...head` resolved its merge base to the source itself: empty diff, empty stat, empty commit list on every merged MR. Now guarded by `git::is_ancestor(head, target_branch)`, falling through to `(merge^, merge)` — the same endpoints the deleted-branch case already used.
- Rebase-merged MRs deliberately keep branch-to-branch comparison: replayed commits carry new shas, so the source is not contained in the target and `is_ancestor` is false.

## Added

- `<datalist id="release-tags">` on the create-release form's `tag` field, mirroring `merge-refs` on the new-MR form. Candidates come from `Manifest::refs` (`refs/tags/` prefix) minus `Remote::list_release_tags`, sorted; built only when `can_write` (the form itself is gated on it). Logic in `releases::taggable_tags`, unit-tested apart from the render.
