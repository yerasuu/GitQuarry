# v0.4.0

Range: `v0.3.0..v0.4.0`. Every crate in the workspace moves `0.3.0` ->
`0.4.0`; they share one version so a deploy can be named by a single number.

Minor rather than patch for two reasons: pull requests are called merge
requests now, which moves their URLs and their storage, and the storage
engine underneath moved to `s3db` v0.4.2, which an existing bucket has to be
migrated for. Both need a step at deploy time — see **Ops**.

## Changed

- **Pull requests are merge requests.** The rename is total: the tab, the
  page copy in both locales, the `/_merges*` form targets, the `merges` /
  `merge` / `new_merge` views, the audit actions (`merge_request.*`), and
  the per-repo storage prefix (`repos/<uid>/merges/`). Nothing about how
  they work changed — this is what they are called. Links and bookmarks
  under the old paths stop resolving.
- **A failed password login slows that username down instead of locking it
  out.** Five wrong guesses used to bar the account for fifteen minutes,
  which is a denial of service anybody could aim at anybody: knowing a
  username was enough to keep its owner out. Now attempts past the cap wait,
  doubling per failure to a ten-second ceiling, and the person who actually
  knows the password still gets in. Guessing costs exactly as much as
  before.
- **Enabling or disabling two-factor auth ends the sessions that predate
  it**, the same way changing a password already did. A session established
  under one set of rules shouldn't outlive the decision to change them.
- New password hashes are written at a higher Argon2id cost (64 MiB, three
  passes). Existing hashes keep verifying under whatever cost they were
  written with, and are rewritten at the new one the next time that password
  is set.

## Added

- **`trust_forwarded_for` in `gitquarry.toml`.** Behind a reverse proxy every
  anonymous git request arrives from the proxy's address, so the clone/fetch
  rate limit put the whole world in one bucket and one noisy client could
  spend it for everybody. With this on, the limit keys on the first
  `X-Forwarded-For` hop instead. Off by default, and it has to stay off
  unless a proxy in front of this server *overwrites* that header — a client
  free to set it picks its own bucket, which is worse than sharing one.

## Fixed

Most of this release is a security pass over the whole tree. The findings
below were found by reading, not reported from outside.

- **The admin pages were open on an instance with no login configured.** The
  gate that protects `/_settings`, `/_users`, `/_audit`, `/_new` and every
  repo's settings tab skipped every check while no user had a password and
  no OIDC was set up — the bootstrap window. Anyone who could reach the port
  during it could create an admin account and close the door behind them.
  That window now needs a token the process prints to stderr at startup,
  exchanged once at `/_bootstrap?token=…` for a short-lived grant. It dies
  with the process, and is refused outright once a login method exists.
- **An unauthenticated request could fill the disk.** The release-asset
  upload read the whole multipart body — up to the 2 GB ceiling, straight to
  local disk — before checking whether anyone was logged in. The session
  check now happens before the body is touched.
- **OIDC accepted an unverified email, and skipped two-factor.** Identity on
  that path is the email and nothing else, so a provider that merely omits
  `email_verified` let an attacker who could register an address at the IdP
  sign in as the account holding it. Nothing short of an explicit `true` is
  accepted now. The callback also honours `totp_enabled`, which it didn't:
  an account with 2FA enrolled was being logged in with one factor.
- **A mirror's forge token was visible to every account on the server.** It
  travelled in `git`'s command line, and `/proc/<pid>/cmdline` is
  world-readable. It goes through the environment now, via a credential
  helper, and the URL on the command line carries no secret.
- **The second-factor step took no CSRF token**, alone among the mutating
  endpoints — the one that completes the very login flow the token on
  `/_login` exists to protect.
- **A commit signed by an expired or revoked key showed as verified.**
  `gpg --verify` exits 0 for those, and its exit status was what the check
  read. It reads the machine-readable status output now.
- **A TOTP code could be used twice.** A code is valid across three 30-second
  steps, so an observed one stayed usable for up to 90 seconds after its
  owner logged in. The step is spent on use.
- Basic-auth over git-smart-HTTP no longer answers faster for a username
  that doesn't exist, mirroring what the web form already did.
- `/_metrics` no longer publishes the build version — it is unauthenticated,
  and the version is the one field there that only helps someone matching
  the instance to a known bug.
- The forge API clients no longer follow redirects: the instance host
  allowlist decides where a mirror makes this server open connections, and a
  302 from an allowed host would hand that decision to somebody else after
  the check had passed. `git` is told the same.
- A download's filename can't break out of its `Content-Disposition` quoting
  any more, and the short-sha helper no longer slices a multi-byte character
  in half.

## Ops

Two steps, in this order, for a bucket that already holds data. The server
can't serve during them.

1. **`s3db-inspect … migrate-bootstrap --apply`** if the bucket was
   bootstrapped before the data key was wrapped (the command prints the
   current config first — keep it). It rewrites one small object,
   `.conf/encryption.json`, wrapping the key the bucket already uses.
   Nothing is re-encrypted, and restoring the old file reverts it.
   A binary older than this release cannot open a migrated bucket, and this
   one cannot open an unmigrated one.
2. **`gitquarry backfill-repo-index --bucket <name> --apply`.** The
   repo-name index moved to an encoded key segment, because a repo's full
   name carries the `/` between namespace and local name and the storage
   engine now refuses that inside one segment. Until this runs, existing
   repos don't resolve by name. It is a dry run without `--apply`, and
   idempotent.

A first boot on an empty bucket needs the bootstrap token from the process's
own stderr — see **Fixed**. It is printed only while no login method exists.
