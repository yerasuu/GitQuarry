# v0.4.0

Range: `v0.3.0..v0.4.0`. Workspace `0.3.0` -> `0.4.0`. Breaking: routes, storage prefix and bucket encryption envelope all move. See **Ops**.

## Changed

- Pull requests renamed to merge requests throughout: `domain::merge_request`, `storage::merge_requests`, `webui::repo::merges`, `wire::MergeRequestMeta`/`Mr*`, i18n `web::repo_merges`. Routes `/_pulls*` -> `/_merges*`, views `pulls|pull|new_pull` -> `merges|merge|new_merge`, audit actions `pull_request.*` -> `merge_request.*`, storage `repos/<uid>/pulls/` -> `repos/<uid>/merges/`. GitHub/Codeberg REST paths and their DTOs keep upstream vocabulary (`/pulls`, `GhPullRequest`).
- `LoginAttempts` replaces the flat lockout with `penalty()`: zero under `LOGIN_MAX_ATTEMPTS`, then doubling per failure to `LOGIN_MAX_PENALTY` (10s). A username-keyed lockout was a DoS anyone could aim at anyone. Applied in `git::http::authenticate`, `auth::web::login` (both steps) and `reauth::require_reauth_throttled`.
- `session_epoch` bumps on `confirm_totp` and `disable_totp`, not only `set_password`.
- New password hashes use Argon2id at 64 MiB / t=3 / p=1 (`password::hasher`); verification still reads the cost from the stored PHC string.

## Added

- `trust_forwarded_for` in `gitquarry.toml` (default off) -> `AppContext`, read by `git::http::client_key`: keys the anonymous rate limiter on the first `X-Forwarded-For` hop instead of the socket address.

## Fixed

- `settings::web::require_admin` and `repo_settings::require_repo_authority` skipped every check while `login_enforced` was false, leaving `/_settings`, `/_users`, `/_audit`, `/_new` and repo settings open on a not-yet-bootstrapped instance. That window now requires `webui::bootstrap::TOKEN` (192-bit, stderr at startup), exchanged at `/_bootstrap?token=…` for a sealed 1h grant cookie; refused once a login method exists.
- `handler_upload_asset_post` drained the multipart body (2 GB cap, streamed to a tempfile) before `require_login`. Session check hoisted above the loop.
- OIDC callback accepted a missing `email_verified` (now requires `Some(true)`) and ignored `totp_enabled` (now diverts to `/_login_totp`).
- Mirror token left `git`'s argv, where `/proc/<pid>/cmdline` is world-readable. Now passed through `GITQUARRY_MIRROR_TOKEN` and a `credential.helper`, with `credential.interactive=false` and `http.followRedirects=false`.
- `/_login_totp` took no CSRF token; now anchored on `PENDING_TOTP_COOKIE`.
- `gitquarry_gpg::verify_detached_signature` read `gpg`'s exit status, which is 0 for `EXPKEYSIG`. Now parses `--status-fd` and requires `GOODSIG` without `EXPKEYSIG`/`REVKEYSIG`/`BADSIG`/`ERRSIG`/`NO_PUBKEY`.
- TOTP codes were replayable across their ±1-step window. `User::totp_last_step` is spent via `domain::user::record_totp_step` under CAS before the session is issued.
- `git::http::authenticate` skipped Argon2 for an unknown username (timing oracle); now verifies against `password::DUMMY_HASH`.
- `/_metrics` no longer emits `gitquarry_build_info{version}`; lockout gauge renamed `gitquarry_login_penalised_active`.
- Forge clients build with `redirect(Policy::none())`.
- `export::attachment` strips quotes/backslashes/control chars from `Content-Disposition` filenames; `validate::short_sha` uses `get(..n)` instead of a byte slice.

## Ops

1. `s3db-inspect … migrate-bootstrap --apply` if `.conf/encryption.json` predates the wrapped data key. Rewrites that one object; no re-encryption; restoring the old file reverts it. Old and new binaries cannot open each other's buckets.
2. `gitquarry backfill-repo-index --bucket <name> --apply`. `REPO_NAME_INDEX` moved from `Segment::Raw` to `Segment::Base64` (a full name carries a `/`, which s3db now refuses inside a segment). Until it runs, existing repos don't resolve by name. Dry run without `--apply`, idempotent.

First boot on an empty bucket needs the bootstrap token from stderr.
