# v0.4.4

Range: `v0.4.3..v0.4.4`. Workspace `0.4.3` -> `0.4.4`. No deploy step.

## Fixed

- `style/app.js`'s `data-async` submit handler: a failed request left every optimistic paint (toggle label, count, `data-html-attr`/`data-class-target`) stuck on the guessed value with no visible error. `fetchFragment` now reverts each one to its pre-submit value and shows a toast (`showErrorToast`, `window.Styler.toast`) instead.
- The toast's message: `AsyncRequestError`/`extractFlashMessage` pull the actual text out of the failed response's own `flash::render_flash(Flash::Err(...))` markup (the same `AppError::into_response` already renders) instead of always showing a generic string — that fallback (`data-error-generic`, `gitquarry_i18n::web::chrome::async_request_failed`) now only fires for a request that never reached the server at all.
- `fetchFragment`: an exception thrown *inside* the success callback (a stale `data-async-target` selector) no longer falls into the same path as a real request failure — it used to trigger the same rollback/toast as a failed request even though the server had already applied the change.
- Two `data-async` forms repainting the same node could race each other's response (star+watch -> `#community-stats`, the three text-size buttons -> `#about-body`, two MR-action forms -> `#mr-actions`). Replaced the per-form `_gqRequestSeq` counter (which only guarded the failure path, not success) with a `_gqLocked` flag set on every node a submit touches; a second submit reaching any of those nodes is dropped until the first settles.
- `[data-copy]`'s clipboard-write failure now surfaces a toast instead of only logging to the console.
- `webui::error::AppError::into_response` always rendered in `Locale::DEFAULT` regardless of the visitor's actual pick. `webui::request_cache_middleware` now resolves `locale_pref::effective_locale` once per request into a new `locale_pref::CURRENT_LOCALE` task-local (scoped alongside `REQUEST_BACKEND`/`CURRENT_USER_MEMO`), which `AppError::into_response` reads via `try_with`.

## Added

- `/_account/appearance` gained a fourth preference — default language (`User.locale_default`: `""`/`"es"`/`"en"`) — alongside text size/theme/density. `gitquarry_i18n::shared::invalid_locale` validates the posted value; `auth::i18n::appearance::locale_*` carries the page copy.
- `webui::repo_settings`: the repo settings tab split from one page stacking all 13 sub-forms into 13 separate `?view=settings_<id>` pages sharing a sub-nav row (`page_chrome::project_subnav`, `repo_settings::settings_sections`) — same "GitHub-style separate pages" treatment `/_account/*` already had; the general/description section keeps the bare `?view=settings` id. `render_settings_page` is gone, replaced by `render_settings_section(section, ...)`; `handler_repo_conf_post` now re-renders only the one section a `POST`'s action belongs to (`section_for_action`), not the full stack.
