# v0.3.0

Range: `v0.2.0..v0.3.0`. Every crate in the workspace moves `0.2.0` ->
`0.3.0`; they share one version so a deploy can be named by a single number.

Minor rather than patch because a repo can now mirror itself to an outside
forge, and because forking changed shape: a fork no longer arrives carrying
the upstream's pull requests or held LFS locks.

## Added

- **A repo can mirror itself to GitHub, GitLab or Codeberg**, in either
  direction or both. Each mirror is a row on the repo's settings tab with
  its own URL, token, direction and per-ref status. Refs move only on a
  real fast-forward: when the two sides have genuinely diverged the ref is
  marked as such and neither side is forced, and a branch deleted on one
  side is never re-created from the other. What a mirror pulls in has to
  pass the same rules a push would — protected branches and tags, required
  signatures, the LFS blob ceiling and the owner's storage quota — because
  those are properties of the repo, not of the transport that brought the
  commits.
- **Pull requests sync too, if you turn it on per mirror.** Titles,
  descriptions, open/closed state, merges and comments travel both ways,
  with each side remembering what it has already sent so a comment can't
  echo back and forth. A pull request opened from a fork on the external
  side is skipped rather than retried forever: its branch lives in that
  fork, so there is nothing here to open it against.
- **An instance decides which hosts a mirror may reach.** The three public
  forges this build has a client for are always allowed; the settings page
  takes any extra hosts, including `*.` patterns for a self-hosted GitLab
  or Gitea. Configuring a mirror is what makes the server open a connection
  to a host somebody else chose, so anything outside that set is refused —
  when the mirror is saved, and again before every sync, so narrowing the
  list reaches mirrors that already exist.
- Mirror actions are recorded in the audit log, syncing by hand included —
  that button is the one that reaches a third party immediately rather than
  on the next sweep.

## Changed

- **A fork no longer inherits the upstream's pull requests or its held LFS
  locks.** Duplicating a repo copied every object under it, which is right
  for git data and wrong for a conversation: a fork started life owning
  someone else's review threads. Templates instantiate the same way and had
  the same problem.
- **Configuring a mirror now needs the owner tier**, not the maintainer
  tier that covers ordinary repo settings. A mirror ships the repo's
  contents to a third party and stores a credential for it, which is the
  same order of decision as handing the repo to someone else.
- Deleting a repo stops it being mirrored outward. Deleted repos are
  already invisible to every transport; the periodic sweep was the one path
  that could still reach one, and its owner deleting it is not an
  instruction to keep publishing it.

## Fixed

- **A fork carried away the original's mirror credential.** Because a copy
  took every object under the repo, forking one with a mirror configured
  handed the new owner a working token for the original owner's account on
  the external forge — usable as-is, and repointable at a host of their
  choosing. Fixed by the same change that stops pull requests being copied:
  a duplication now strips what it must never inherit.

## Ops

- Sync cadence: every repo with an enabled mirror is swept every 15 minutes,
  four repos at a time, and a clone or fetch triggers a sync for that repo
  at most once a minute. A push doesn't trigger one at all — pulling from
  the far side and then accepting the push is how a valid push gets rejected
  as stale.
- No mirror sync can hang a git operation: a call to an external forge is
  killed after 5 minutes, the sync a clone triggers is abandoned after 5
  seconds, and either way the clone is served from what is already local.
- Whatever the far side says about a failure is kept, redacted of any
  credential and capped in length, on the mirror or the individual ref, and
  shown on the settings tab.
