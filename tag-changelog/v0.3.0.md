# v0.3.0

Range: `v0.2.0..v0.3.0`. Workspace `0.2.0` -> `0.3.0`. Minor: outward mirroring, and forking stops copying what it must not inherit.

## Added

- `gitquarry-mirror-external` + `gitquarry-forge-clients`: per-repo `ExternalMirror` (url, token, `SyncDirection::{PushOnly,PullOnly,Bidirectional}`, `enabled`, per-ref status) against GitHub, GitLab and Codeberg. `engine::plan_ref_sync` moves a ref only on a real fast-forward; a divergence is recorded as such, and a deletion on one side is never replayed onto the other. Pulled refs go through `mirror::policy` — protected branches/tags, required signatures, LFS ceiling, owner quota — because those belong to the repo, not the transport.
- Optional PR sync per mirror (`sync_pull_requests`, default off): title, description, open/closed, merges and comments both ways, with per-side cursors and `synced_remote_comment_ids` so a comment can't echo. A PR opened from a fork on the external side is skipped: its head branch isn't reachable from here.
- Instance host allowlist for mirror targets. Built-in forge hosts are always allowed; `ServerSettings::mirror_extra_hosts` adds more, `*.` patterns included. Enforced by `validate::check_host_allowed` at save time *and* before every sync, so narrowing the list reaches mirrors that already exist.
- Mirror actions land in the audit log, manual sync included.

## Changed

- Fork and template instantiation no longer copy `pulls/`, `lfs-locks/` or `mirrors/` (`domain::repo::NOT_INHERITED_BY_A_COPY`). A copy took every object under the repo, so a fork started life owning someone else's review threads.
- Configuring a mirror needs the owner tier, not maintainer: it ships repo contents to a third party and stores a credential for it.
- `domain::repo::delete` stops outward mirroring; the periodic sweep was the one path that could still reach a deleted repo.

## Fixed

- A fork carried away the original's mirror credential — a working token for the upstream owner's account on the external forge, repointable at any host. Same fix as the PR copy: a duplication strips what it must never inherit.

## Ops

- `SYNC_INTERVAL` 15 min, `REPO_SYNC_CONCURRENCY` 4; a clone or fetch triggers a sync for that repo at most once a minute. A push triggers none — pulling first is how a valid push gets rejected as stale.
- `GIT_OP_TIMEOUT` 300s per call to a forge; the sync a clone triggers is abandoned after 5s and the clone is served from what is already local.
- Far-side failures are stored on the mirror or the ref, redacted of credentials and capped at `MAX_ERROR_LEN` (500), and shown on the settings tab.
