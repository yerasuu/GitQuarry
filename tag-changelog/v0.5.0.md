# v0.5.0

Range: `v0.4.5..v0.5.0`. Workspace `0.4.5` -> `0.5.0`. No deploy step.

## Breaking

- Minimum supported Rust version raised to 1.98 (`workspace.package.rust-version`, `deploy/Dockerfile`'s builder stage). Building from source needs a toolchain at least that new.

## Added

- `auth::domain::group`: groups drop the old team abstraction for direct members with a role, and can now nest as subgroups under an existing group (`access::groups::create_subgroup`). `access::access::groups` indexes the groups a user belongs to and resolves permissions through the ancestor chain, so a permission granted on a parent group reaches every subgroup and repo under it. `webui::auth::web::group` adds a group page listing its repos, subgroups and members; `webui::auth::web::groups` offers only the namespaces the viewer may actually create in.
- `webui::auth::web::repos`: a repos dashboard split into personal, group and granted-access sections.
- `domain::repo`: repos gain a free-text `display_name` alongside the URL slug (`validate::slugify`), shown across the index, activity list, breadcrumbs, page heading, atom feed title, search hits, favorites, PAT scopes, admin grants and cross-fork MR source. `domain::repo::backfill_display_name` derives both for legacy repos on listing so existing repos don't need a manual pass.
- `gitquarry_core::backup`: a full backup subsystem — `backup::inventory` classifies every bucket key for backup purposes, `backup::replica` mirrors a bucket to another bucket at the same keys, `backup::snapshot` writes a versioned snapshot of the mutable config set, `backup::prune` enforces a configured retention on the destination, and `backup::schedule` runs the job on a schedule (`ServerSettings`'s new backup fields) or once via the new `gitquarry backup`/`gitquarry restore` operator commands (`gitquarry_domain::commands::{backup,restore}`). `webui::settings::web` gained the `/_settings` backup section to configure and trigger it from the UI.
- `gitquarry_core::migrations`: a bucket data-version migration runner, applied automatically at server startup and reachable by hand through `gitquarry migrate`; its first migration (`migrations::group_members`) moves existing groups from the old team shape to direct members.

## Fixed

- `domain::merge_request`: a closed or merged MR's metadata (title, description, labels, ...) can no longer be edited through `webui::repo::merges`.
- `webui::repo::merges`: a merge request form now rejects a stale repo reference instead of operating against the wrong repo.
- `webui::actions`/`webui::repo::summary`/`auth::web::favorites`/`webui::watch`: star/watch counts' DOM ids are scoped by repo uid, so two repo cards on the same page no longer fight over the same element id.
- `auth::web::login`: the repos dashboard link moved out of the account dropdown to its own nav spot.
- `validate`: repo path segments now reject unescaped URL characters instead of accepting them and producing a broken link.

## Changed

- Every `eprintln!`/`println!` used as an error, warning or lifecycle notice across the workspace (core, webui, mirror-external, forge-clients, gpg, domain's operator commands, and the server binary) now goes through `tracing`, with a level picked per site (`error!`/`warn!`/`info!`/`debug!`) instead of one undifferentiated stream. `gitquarry-server::main` initializes the one process-wide subscriber, writing to stderr and honoring `RUST_LOG` (default `info`) — the same filter covers the server, the `pre-receive-hook` subprocess, and every human-run maintenance command. `--help`/`--version` banners stay on `println!`, since they must reach stdout unconditionally.
