# v0.2.0

Range: `v0.1.1..v0.2.0`. Workspace `0.1.1` -> `0.2.0`. Minor: five features, and the account settings URLs move.

## Added

- Instance-signed merge commits. `git::signing::load_or_create` mints an SSH key on first use and keeps it at `.conf/signing_key.json`; `install_allowed_signers` writes it into each mirror and points `gpg.ssh.allowedSignersFile` at it, so `%G?` resolves. Author stays whoever merged, committer becomes `GitQuarry <instance@noreply.gitquarry>` — required for git to verify at all. Rendered in a colour distinct from an account's own signature: the instance attests that it built the commit, not who wrote it.
- `MergeStrategy::FastForward`, a fourth strategy that creates no commit, so the author's own commits and signatures are what land. `domain::pull_request::fast_forwardable` gates the button; disabled with a reason once the branches diverge.
- `domain::pull_request::conflicts` (a `git merge-tree` dry run) puts the conflicting paths and the commands to resolve them on the PR page. A failed merge returns there instead of an error page that lost the list on reload.
- Footer on every page: copyright, licence, running version. `/_changelog` serves the release notes for the exact version running and `/_license` the AGPL text, both compiled into the binary — which is what the licence obliges an operator to offer a network user, and what a link to gnu.org doesn't discharge.
- An account can change its own primary email where OIDC isn't configured. With OIDC that address decides which account a login lands on, and there is no mail transport here to verify ownership with.

## Changed

- Account settings split into profile (avatar, emails), security (password, 2FA, recovery codes) and keys (SSH, GPG). `/_account/keys` is new; `/_account/security` no longer holds keys or email addresses.
- Account, instance and per-repo settings pages share one card layout with labelled fields.
