# v0.2.0

Range: `v0.1.1..v0.2.0`. Every crate in the workspace moves `0.1.1` ->
`0.2.0`; they share one version so a deploy can be named by a single number.

Minor rather than patch because of the five features below, and because the
account settings URLs moved: `/_account/keys` is new, and
`/_account/security` no longer holds SSH keys, GPG keys or email addresses.

## Added

- **The instance signs the commits it builds.** A pull request's merge,
  squash or rebase commit is signed with an SSH key the instance generates
  on first use and keeps in its own bucket — no key to place, no path to
  configure. The commit's author stays whoever merged; its committer becomes
  the instance, which is what lets git verify the signature at all. Shown as
  verified in a colour distinct from an account's own signature: an instance
  can only attest that it built the commit, never who wrote the code.
- **Fast-forward merges.** A fourth strategy that creates no commit at all,
  so what lands is the author's own commits carrying the author's own
  signatures. Offered next to merge, squash and rebase, and disabled — with
  the reason shown — once the branches have diverged.
- **Conflicts are part of the pull request page.** A branch that can't merge
  cleanly lists the conflicting files and the commands to resolve them
  locally. Pressing merge on one returns you to that page instead of an
  error page that lost the list on reload.
- **A footer on every page**, with the copyright, the licence and the
  running version. Both links serve files compiled into the binary rather
  than fetched from a repo or an outside site: `/_changelog` shows the
  release notes for the exact version running, and `/_license` the AGPL
  text this build is distributed under -- which is what the licence obliges
  an operator to offer a network user in the first place, and what a link
  to gnu.org doesn't discharge.
- **An account can change its own primary email**, but only where OIDC
  isn't configured. With OIDC that address decides which account a login
  lands on, so it stays admin-managed there — no re-authentication makes
  that safe, and there is no mail transport here to verify ownership with.

## Changed

- **Account settings reorganized** into profile (avatar, email addresses),
  security (password, two-factor, recovery codes) and keys (SSH, GPG).
  `/_account/security` had grown into six unrelated blocks on one flat page,
  mixing identity, login credentials and signing keys.
- Every settings page — account, instance and per-repo — now uses one card
  layout with labelled fields. The `div.field` markup it relies on had
  existed for a while with no CSS rule at all, which is why forms reached
  for placeholder-only inputs instead of labels.
- Changing your own password asks for it twice. A password field shows
  nothing back, so a typo silently became the new password — and for an
  account with no other way in, that is a lockout with no recovery path.
- Avatars take their size from the surrounding text instead of fixed pixels,
  so they keep their proportion to the name beside them under both densities
  and all three text sizes. Uploaded photos are square with soft corners
  like the generated identicons, rather than circles.

## Fixed

- **A cached signature verdict outlived the keys it was based on.** The
  cache was keyed by commit sha alone, but the answer also depends on who
  claims the author's email and which keys that account has registered. A
  `None` cached before you registered your key kept the commit unverified
  forever, and — worse — a verdict kept vouching for a key the account had
  since removed.
- **One address could land in both email indexes at once.** Adding your own
  primary address as a secondary stored it twice with nothing claiming the
  secondary side, and a primary claim never consulted the secondary index at
  all, so one account could take an address another already answered to and
  inherit its commit attribution.
- **Merge commits rendered as empty.** Plain `git show` prints no patch for
  a commit with more than one parent, so every merge — including the ones
  this app creates — showed a file list and no diff at all.
- **A merged pull request 500'd once its source branch was deleted**, which
  the merge form's own checkbox does. It now falls back to what the merge
  landed on the target.
- An instance signature no longer erases the author's avatar on a commit
  row: it says who built the commit, not who wrote it.

## Ops

- One version for the whole workspace: `version`, `edition`, `rust-version`
  and `license` moved to `[workspace.package]`, so a bump is one line rather
  than eight that can silently disagree.
- The changelog page's path is built from `CARGO_PKG_VERSION`, so cutting a
  release without writing its notes file fails the build instead of shipping
  a page that describes the previous one.
- The deploy image installs `openssh-client` and `gnupg`. Git shells out to
  `ssh-keygen` to make the instance's signatures, and without it a merge
  fails outright rather than landing unsigned; `gpg` is what verifies an
  account's own key, so registering one failed on the image as shipped.
