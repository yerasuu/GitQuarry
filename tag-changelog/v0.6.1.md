# v0.6.1

Range: `v0.6.0..v0.6.1`. Workspace `0.6.0` -> `0.6.1`. Not breaking: new commands, optional `#[serde(default)]` fields and new bucket prefixes only. See **Ops**.

## Added

- Publish mirrors, `gitquarry_mirror_external::publish`: a private repo published, filtered, to a public remote. `PublishMirror` entities live in `repos/<uid>/publish-mirrors/<id>` (`Collection::new_owned`), one per mirror, with `remote_url` (checked against the instance host allowlist at save and at every run), `token` (`MirrorToken`, `Debug` prints `<redacted>`), `enabled`, `mode`, `filter_epoch`, `publisher`, `filter`, `publish_branches`/`publish_tags` (short names or `*`/`**` globs under `refs/heads/`/`refs/tags/`), `identities`, `unmapped`, `spdx`, `secret_allowlist`. `validate_publish_mirror` caps the inputs (`validate.rs`: 256 patterns of 256 bytes, ref patterns 200, identity fields 254, SPDX 64).
- `publish::filter`: `.gitignore`-glob include/exclude from the entity plus `.gitquarry/publish.toml` in the source ref, which can only add exclusions (effective filter = union). `NEVER_PUBLISHED_REF_PREFIXES` (`refs/merge-requests/`, `refs/notes/`, `refs/gitquarry/`) is checked again on every selected ref.
- `publish::audit` gates, all blocking: excluded-blob set, identity map (`UnmappedPolicy::Block` by default, `Passthrough` optional; `IdentityMapping` matches `private` case-insensitively), SPDX declaration, secret scan. `publish::secrets`: credential-shape regexes plus Shannon entropy (assignment to a secret-sounding name >= 3.5 bits, `TOKEN_MIN_LEN` 40 with >= 4.5); text blobs over `MAX_SCAN_BYTES` (8 MiB) are reported as unscanned; a finding names rule and line, never the text. `SecretAllow` dismisses a finding by `path` + blob `sha`.
- `PublishMode::Snapshot`: `publish::snapshot` writes one commit per run (author/committer `Publisher`, fixed message from `snapshot_message`) holding the filtered tree of each published branch head, on top of the previous snapshot, into a scratch repo that is a fresh `git init` with no alternates; `verify_scratch` checks no excluded blob is in it before the push. Tags are not read. Fast-forward only.
- `PublishMode::History` (`publish::history`): every commit reachable from the published refs rewritten deterministically through the filter (`publish::rewrite`, ids computed in memory; `gpgsig`, `gpgsig-sha256`, `mergetag` headers dropped, tags re-made by `history::tags`), incrementally against a mapping kept in the bucket; matching `publish_tags` are published too. Same filter, same history gives the same public ids.
- `publish::run`: host gate, then every gate of every ref on the objects actually written, then one atomic `git push` of all refs, then the record; one blocked ref blocks the run. A history run forces only onto a new epoch, with a lease. Run from the periodic sweep (`engine.rs`, after the external mirrors; `refresh_mirrors_enabled_index` now counts enabled publish mirrors) and by "publish now" (`publish_mirror_now`, enabled or not).
- Run record in `repos/<uid>/publish-log/<mirror_id>` (`PublishLog`, newest `MAX_RUNS` = 20 runs, at most 20 findings per gate), apart from the entity so a sweep never loses a CAS race against an open edit form.
- Epochs, `publish::epoch`: `filter_epoch` rises by one and only through a confirmed edit (`EpochBumpRequired`) when the output of a history publish changes (mode, filter, identity map; not the secret allowlist, SPDX, unmapped policy or ref patterns). A run compares its `Fingerprint` (entity half plus the `.gitquarry/publish.toml` half) with the one recorded for the epoch and refuses on a mismatch. A log recording heads from before epochs counts as epoch 0.
- Per-epoch bucket data under `repos/<uid>/publish/<mirror_id>/<epoch>/`: `map/<xx>` (private -> public commit and tree, magic `GQS1`), `excluded/<xx>`, `inverse/<xx>` and `objects/pack/` (one pack per run), sharded by the first byte of the id, sealed with the key as AAD.
- Inverse index, `publish::inverse` (`inverse/<xx>`, magic `GQI1`): public commit -> the private commits that map to it, a set per key and a union on store; written by every history run, a corrupt shard is refused whole. `PublishLog::abandoned` (epoch -> unix seconds) records when an epoch stopped being current, set by `epoch::record_bump` on a confirmed bump and by the GC sweep for an epoch with no record.
- `gitquarry publish-gc [--bucket NAME] [--grace-days N] [--repo UID] [--apply]` (`publish::gc`), dry-run unless `--apply`, `DEFAULT_GRACE_DAYS` 30: deletes the data of epochs abandoned past the grace. Never touches a mirror's `filter_epoch` or published epoch, anything above `filter_epoch`, a mirror whose entity or log doesn't read, or data whose mirror is gone (reported only, as are unrecognised keys under `publish/`); `apply` re-reads and re-decides each epoch before deleting.
- `gitquarry publish-inverse-backfill [--bucket NAME] [--repo UID] [--apply]` (`publish::inverse::backfill`): rebuilds `inverse/` of each epoch from its `map/`, add-only and idempotent, for epochs published before the index existed.
- `PublishMirror.inbound_token` (`#[serde(default)]`): the credential for reading the public remote's pull requests, meant to be read-only; empty means none.
- `gitquarry publish-inbound-dry-run --repo OWNER/NAME --mirror ID --pr N --base BRANCH [--provider github|gitlab|codeberg] [--push-token] [--bucket NAME]` (`publish::inbound`): fetches the pull request head into a temporary quarantine bare repo, resolves its base through the epoch's inverse index, overlays each public commit on the private tree and checks that the forward rewrite gives back the pull request's own commits. Writes nothing to the bucket or the private repo; the provider is inferred for github.com, gitlab.com and codeberg.org; `--push-token` uses the push token only when there is no `inbound_token`. Caps: `MAX_PR_COMMITS` 250, `MAX_CHANGED_FILES` 3000, `MAX_BLOB_BYTES` 16 MiB, `MAX_PR_BYTES` 64 MiB, `MAX_QUARANTINE_BYTES` 1 GiB (watched during the fetch), `FETCH_TIMEOUT` 120 s. `Verdict` refuses, among others, merge commits, symlinks, gitlinks, modes other than 100644/100755, excluded paths, `.gitattributes`/`.gitmodules` and CI/`.gitquarry` top-level entries (`SENSITIVE_TOP_LEVEL`), names colliding after Unicode normalisation and case (`icu_normalizer`), a base from an earlier epoch (`OldBaseEpoch`) or a changed filter (`FilterChanged`). Secret findings in what the pull request adds (`SecretFinding`) are reported and never refuse it.
- Repo settings section "publish mirrors" (`webui::repo_settings::publish_mirrors`), `conf_action` `add_publish_mirror`, `edit_publish_mirror`, `delete_publish_mirror`, `preview_publish_mirror`, `publish_mirror_now`; the edit form carries `publish_confirm_epoch_bump`. Preview (`publish::preview`, `MAX_PREVIEW_PATHS` 2000, flags a truncated history) computes the rewritten refs and runs the gates dry; it shows the snapshot commit a publish would push, and says when a publish would push nothing.
- `gitquarry restore --repo UID [<snapshot-id>] [--from DEST] [--apply]` (`backup::restore_repo`): one repo back from the replica (packs, LFS objects, releases, raw ciphertext) and a snapshot (config and other entities, re-sealed; the replica when no snapshot holds the repo). `refs.json` is read first and written last, only if every other object made it; the repo's `deleted_at` is cleared. Needs a replica destination, refuses `--list` together with `--repo`, deletes nothing. `validate::validate_repo_uid` accepts 32 lowercase hex only. Name and listing indexes are not rebuilt: run `backfill-repo-index --apply` after.
- `webui::repo::merges`: a review of an earlier source head shows as outdated (`review_is_current`), unless the branch is gone.

## Changed

- `backup::inventory::classify_repo`: `publish/` is `Class::Entities` except `publish/**/objects/pack/` (`Class::Git`), plus `publish-mirrors/` and `publish-log/`. A mapping is carried, not derived, since a force-push of the private repo can leave it as the only record of what the public side holds.
- The inbound side's fetch and git calls run through `git_remote::isolate`: environment cleared to `PATH` and `PASSTHROUGH_ENV` (`HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, `SSL_CERT_FILE`, `SSL_CERT_DIR` and lowercase forms), no system or user git config, empty `HOME`.
- `gitquarry --help` lists `restore --repo`, `publish-gc`, `publish-inverse-backfill` and `publish-inbound-dry-run`.
- `gitquarry-mirror-external` gains `icu_normalizer`, `regex-lite`, `sha1`, `toml`; `tempfile` moves from dev-dependency to dependency. `.cargo/config.toml` sets `net.git-fetch-with-cli`; `.githooks/commit-msg` (subject <= 72 chars, no AI attribution); `scripts/check-practices.sh` replaces `check-humanization.sh`.
- `refactor`: derives nothing used (`Eq`, `Ord`, `Clone`) dropped from entities and enums; borrow or move instead of clone; inferred `let` types; `println!` of `--help`/`--version` marked as CLI output; the internal API failure and a failed peer list in `push_ban_event` go through `tracing`; `Err(_)` catch-alls justified.

## Fixed

- `domain::merge_request::review`: takes `NewReview { author, verdict, body, seen_head }` and refuses a review whose `seen_head` is no longer `source_head` (`review_of_outdated_head`), so a reviewer can't approve code that has since moved. `MrReview.head_sha` (`#[serde(default)]`, `Option`) records it; `review_summary(reviews, head_sha)` counts an approval only when `review_is_current`, and `merge` judges against the commit it is about to land. A review with no recorded head never counts as an approval; `ChangesRequested` blocks whatever its head. `MrDiff.head_sha` and the `head_sha` form field carry the head the page showed; the internal API's `MrDetail` returns `head_sha` too.
- `storage::thread`: a thread read fails (`reading thread entry <key>`) when an entry doesn't open, instead of listing a shorter thread. An entry deleted between listing and read is still skipped.
- `webui::fork`: a storage failure while resolving the fork namespace answers 5xx (`AppError::is_server_error`) instead of a 4xx bad-namespace message.
- `domain::repo::NOT_INHERITED_BY_A_COPY` adds `publish/`, `publish-mirrors/` and `publish-log/`: a fork or copy no longer inherits a publish mirror's forge token, run log or rewritten repo.
- Inbound quarantine: size capped while the fetch runs (`MAX_QUARANTINE_BYTES`), fetch and later git calls on an isolated environment, names compared by Unicode normalisation and case (`distinct_without_case`), proxy and CA variables passed to the isolated git.

## Security

- Merge-request approvals are bound to the head they reviewed (see **Fixed**): before, a force-push after an approval landed unreviewed code under it. Approvals stored before this release have no `head_sha` and no longer count.
- Publish mirrors keep their credential out of copies: `token` and `inbound_token` are sealed like `ExternalMirror.token`, never printed by `Debug`, and the `publish-mirrors/` prefix is excluded from forks.
- Inbound input from the public side is treated as hostile: capped before work, fsck'd as it arrives, refused whole rather than truncated; the fetch sees no ambient credentials.

## Ops

1. Nothing to run on upgrade: no data migration, no changed config key, flag or route.
2. Merge-request approvals given before the upgrade stop counting; reviewers approve again. A request for changes still blocks as before.
3. New `repos/<uid>/{publish-mirrors,publish-log,publish}/` prefixes appear only once a publish mirror is created. They are in backups, not in forks.
4. `publish-gc` and `publish-inverse-backfill` are dry-runs without `--apply`; run `publish-inverse-backfill` only for epochs published by a build that predates `inverse/`.
5. `restore --repo` leaves the repo's name claim and indexes to `gitquarry backfill-repo-index --apply`.
