# v0.4.3

Range: `v0.4.2..v0.4.3`. Workspace `0.4.2` -> `0.4.3`. No deploy step.

## Fixed

- `webui::security_headers` (`gitquarry-webui/src/webui/mod.rs`) now also sets `Strict-Transport-Security: max-age=31536000; includeSubDomains` and a `Permissions-Policy` denying `geolocation`/`camera`/`microphone`/`payment`/`usb`.
- `git::http::pack_response` read the `upload-pack`/`receive-pack` request body via `axum::body::to_bytes(_, usize::MAX)`; capped at `MAX_PACK_BODY_BYTES` (16 GiB) instead.

## Perf

- Webui responses run through `tower_http::compression::CompressionLayer` (gzip/br/zstd), new direct dependency.
- `/_assets/app.js`/`/_assets/styler.js` serve with a sha256 `ETag` and `Cache-Control: public, max-age=31536000`; `304` on a matching `If-None-Match`.
- `storage::build_backend` wraps the raw driver in `s3db::build_resilient_backend` (concurrency caps, retry/backoff, circuit breaker, cross-request raw-bytes LRU) instead of handing it back bare. `BucketConfig.resilience: s3db::ResilienceConfig` (optional, `#[serde(default)]`), surfaced in `gitquarry.toml` as `[buckets.<name>.resilience]` / `.resilience.cache`.
- `webui::repo::summary::render_about` shares one root `git ls-tree` across `render_readme`/`render_sidebar` (was 4 separate spawns per page).
- `webui::highlight::highlighted_lines` (blob view) and `webui::markdown::render` (readme) now run on `tokio::task::spawn_blocking`.
- `russh::server::Config.nodelay = true` on the ssh:// listener.
- `login::current_user` memoized for the rest of the request via a `CURRENT_USER_MEMO` task-local, scoped alongside `REQUEST_BACKEND` in `webui::request_cache_middleware`.
- `AppContext::visible_repo_uids`: new `VisibleRepoUidsCache` (10s TTL) over `storage::settings::list_visible_repo_uids`'s uncached `list_prefix` call, backing the repo index and cross-repo search. Warmed once in `serve::run` before either listener binds.
- `mirror::sync_bare_repo_from_s3` diffs the manifest's refs against the mirror's current ones and applies every create/update/delete in one `git update-ref --stdin` call (`git::apply_ref_changes`) instead of one `git update-ref`/`update-ref -d` subprocess per ref, on every `info/refs` and `upload-pack`.
- `mirror::sync_bare_repo_from_s3` skips the pack list and ref diff entirely when the manifest's CAS etag matches the `.gitquarry-synced-etag` marker already inside the mirror — packs are always uploaded before the manifest CAS that references them, so an unchanged etag proves nothing to sync.
- `mirror::gc::prewarm_recent_mirrors`: spawned detached at startup, re-syncs every mirror still within `mirror_max_age` (default `3d`) of its last access, 4 at a time.
