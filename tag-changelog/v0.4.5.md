# v0.4.5

Range: `v0.4.4..v0.4.5`. Workspace `0.4.4` -> `0.4.5`. No deploy step.

## Added

- `serve::run` registers a `RepoEvent::Push` consumer on `ctx.events` that writes a `repo.push` audit entry (`storage::audit::record`) for every real git push over ssh/HTTP, detached via `tokio::spawn` so the pusher never waits on it. Previously the audit log only ever saw webui-driven actions.
- `webui::repo::mod`'s index page: a stats strip, an activity/clone sidebar (later swapped to a browse-by-topic list, `308397a`/`014998e`), a per-card ssh clone hint, and a card/compact-table density toggle for the repo listing.
- A new-repo button next to the index search form, and a real groups nav link plus pickaxe logo mark on the sticky topbar (`page_chrome`).
- `storage::entities`/`settings::web`: an instance-level source-link setting surfaced in the footer.
- Repo settings (`webui::repo_settings`), account settings (`auth::web::{keys,pat,security,avatar}`), admin actions (`auth::web::users`, `settings::web`), and destructive actions (tag/branch/release/comment delete, MR close/merge/bulk) all gained a confirm-before-submit step, and their forms submit async (`data-async`) instead of a full page POST — including `/_settings` itself, which used to leave F5 asking to resubmit.
- `webui::repo::activity`: the home page's recent-activity rail now describes push/release/MR events instead of raw repo names (`gitquarry-mirror-external/src/engine.rs` feeds the same event shape). `domain::repo` drops low-value entries from a repo's own activity feed.
- `storage::settings`: a repo's last-push timestamp, shown on the home page's repo cards.

## Fixed

- `domain::merge_request`: landing a merge on the repo's default branch now stamps last-push, matching a real push — previously only `git::http`/`git::ssh` did.
- `auth::domain::group`: a group's creator is now added as its first owner; `auth::web::groups` shows a just-created group immediately instead of relying on LIST to catch up.
- `auth::web::keys`'s add-key form: fixed a latent DOM-corruption bug on its error path while switching it to async submit.
- `webui::style::base`: the language dot's margin no longer clamps to a stale `0.15em`; the new-repo button matches the search button's size; the index page's topic pills are outlined instead of styler's filled badge; the sidebar's activity/topics match the mockup instead of a generic community-list.
- `server::boot`'s cipher-fetch failure message now explains that the fetch already retried before failing, instead of reading like a first attempt.

## Changed

- `gitquarry-i18n`: every `msg!` catalog (webui, auth, repo, shared) moved out of `gitquarry-webui`/`gitquarry-core` into the `gitquarry-i18n` crate, then split further — shared into per-domain submodules, web into `auth/` and `repo/` subdirectories.
- `webui::repo_settings`: the 13-section settings subnav moved from `page_chrome` into a sidebar (`repo_settings::mod`); `webui::settings::web` gave each `/_settings` section its own real route and the same sidebar layout as every other config page.
- `webui::repo::activity` split from the audit log, scoping last-push to the repo's default branch.
