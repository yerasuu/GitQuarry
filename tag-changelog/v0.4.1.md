# v0.4.1

Range: `v0.4.0..v0.4.1`. Workspace `0.4.0` -> `0.4.1`. No deploy step.

## Changed

- `s3db` pin `v0.4.2` -> `v0.4.3` in the four manifests that carry it. The library half is unchanged; the tag exists so a deployment names the `s3db-inspect` build that matches its bucket:
  - `rebind <key> --from <old-key> [--apply]` re-seals an object whose ciphertext was copied to a new key. AAD is the object's own storage key, so a server-side copy or prefix rename leaves bytes that authenticate against a key they no longer live at, and the object reads as corrupt.
  - `get` checks `Cipher::is_stream_sealed` before `open`, so a chunk-sealed object (release asset, pack) is named as such instead of reported as a decrypt failure.
  - The three s3db crates inherit `version`/`edition`/`rust-version`/`license` from `[workspace.package]`.
