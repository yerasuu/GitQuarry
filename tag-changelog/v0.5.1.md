# v0.5.1

Range: `v0.5.0..v0.5.1`. Workspace `0.5.0` -> `0.5.1`. No deploy step.

## Added

- Client-side syntax highlighting via a vendored `highlight.js`
  (`crates/gitquarry-webui/src/webui/style/vendor/hljs.js`,
  `hljs-line-numbers.js`, `hljs-light.css`/`hljs-dark.css` —
  `scripts/vendor-hljs.sh`/`scripts/gen-hljs-theme.py` re-vendor on a
  version bump) replaces the old server-side `syntect` highlighter
  (`webui::highlight`, removed, along with the `syntect` dependency).
  `repo::blob::render_blob` emits one `<pre><code id="blob-code"
  class="language-*">` block per file; `app.js` runs
  `hljs.highlightAll()` plus the line-numbers plugin against it,
  reconstructing the `#L42` permalink anchors the plugin doesn't provide
  on its own. Every diff renderer (`repo::components::color_diff`/
  `side_by_side_diff`, `repo::merges::annotated_diff`) wraps each line's
  content in its own `<code class="language-*">` fragment
  (`repo::diff::code_fragment`, via the new `webui::language_tag` helper)
  instead of tokenizing server-side. Two new routes: `/_assets/hljs.js`,
  `/_assets/hljs-line-numbers.js`.
- `webui::mod::versioned_asset_url`: `app.js`/`styler.js`/`hljs.js`/
  `hljs-line-numbers.js` now carry a content hash in their URL
  (`app_js_url`/`styler_js_url`/`hljs_js_url`/`hljs_line_numbers_js_url`),
  served `immutable`, same as `style.css` already was — a changed asset is
  a changed URL instead of a stale year-long cache.
- `repo::components::side_by_side_diff`: each side of the split diff view
  gets its own line-number gutter (4-column layout — old lineno, old code,
  new lineno, new code — GitHub's own split-view convention), via
  `repo::diff::Row`'s restored `old`/`new` line tracking. `table.diff-split`
  gets `table-layout: fixed` plus an explicit `<colgroup>` so both sides
  stay exactly half width regardless of content, and `white-space:
  pre-wrap`/`overflow-wrap: break-word` so a long line wraps within its
  own column instead of forcing a horizontal scrollbar.

## Fixed

- `webui::repo_new`: creating a repo now redirects to the new repo's own
  page. The form was `data-async`, but `handler_new_post`'s success path
  is a `303` — `fetch()` followed it and handed the submit handler the
  destination page's full HTML to graft into `#new-repo-body` as a
  fragment instead of navigating there. The form is a plain POST now,
  same pattern `move_repo`/`delete_repo` already use.
